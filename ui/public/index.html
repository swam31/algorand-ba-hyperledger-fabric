Algorand BA* vs Stock Fabric Raft

Same machine, same four orderers, same peers, chaincode, batch size (500) and load. The Raft orderer is compiled from the same Fabric 2.5.16 source with our consensus module left out, so the only difference is how blocks are ordered.

Crash one orderer under load

20 clients submit continuously and, like a normal client, give up on a transaction after 10 s and send the next one. One orderer is stopped at 20 s and restarted at 40 s. For Raft the victim is the leader (its worst case). Algorand has no leader, so any orderer will do.

Bad Network Experiments (Weak Synchrony, Paper §7.4)

Delay, loss or a total cut applied with Linux netem to the orderers' consensus traffic only (port 7060), under 90 s of load each. Afterwards the fault is removed and we time how long until all four orderers hold the identical chain: same height and same last block hash. Blocks are hash-chained, so that proves no fork happened.

Scale Simulation: 4 to 10,000 Nodes

The real BA* engine (signatures, sortition, vote counting) run in-process with thousands of nodes, each holding $1,000 as its stake. The network is a shared lossless inbox, so this shows how the protocol's work grows with the number of nodes, not internet latency. The paper's claim is that the committee stays about the same size however many nodes join.
